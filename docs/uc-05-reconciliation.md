# UC-05: Ежедневная финансовая сверка

> **Проект:** Интеграция MarketHub ↔ FastDelivery
> **Приоритет:** Should Have (MVP)
> **Автор:** Системный аналитик
> **Дата:** Июнь 2026

---

## Primary Actor
**Финансовый отдел MarketHub** — нуждается в автоматической сверке выполненных заказов для закрытия месяца и оплаты услуг FastDelivery.

**Вторичный актор:** Система (процесс запускается автоматически по расписанию).

## Stakeholders & Interests

| Стейкхолдер | Интерес |
|-------------|---------|
| **Финансовый отдел (Главный бухгалтер)** | Хочет автоматическую сверку вместо 16 часов ручного труда. Хочет акт в формате, совместимом с 1С |
| **Руководитель логистики** | Хочет видеть расхождения для оперативного разбора (почему заказ есть в OMS, но не у FastDelivery) |
| **FastDelivery** | Хочет своевременной оплаты и согласованного формата актов |
| **CTO MarketHub** | Хочет, чтобы сверка не нагружала продовую БД в пиковые часы |

## Preconditions
1. Прошёл расчётный период (сутки)
2. Интеграционный сервис имеет доступ к API сверки FastDelivery: `GET /v1/reconciliation`
3. Запущено по расписанию (cron): ежедневно в 03:00 по Москве (минимальная нагрузка на прод)

## Trigger
Срабатывание планировщика (cron) в 03:00 MSK. ИЛИ главный бухгалтер вручную запрашивает сверку за произвольный период в админке.

## Main Success Scenario

| Шаг | Система | Действие |
|:---:|---------|----------|
| 1 | Планировщик | Запускает процесс сверки за предыдущие сутки (с 00:00 до 23:59) |
| 2 | Интеграционный сервис | Запрашивает из OMS список заказов, завершённых за период: `orderId`, сумма, статус (`DELIVERED`, `CANCELLED`, `RETURNED`) |
| 3 | Интеграционный сервис | Запрашивает у FastDelivery акт за тот же период: `GET /v1/reconciliation?period=2026-06-01` |
| 4 | FastDelivery | Возвращает список заказов: `deliveryOrderId`, `originalOrderId`, сумма, статус |
| 5 | Интеграционный сервис | Выполняет сопоставление (reconciliation) по `originalOrderId` и по сумме |
| 6 | Интеграционный сервис | Формирует отчёт: полные совпадения, расхождения по сумме, заказы только в OMS, заказы только у FastDelivery |
| 7 | Интеграционный сервис | Сохраняет отчёт в формате, совместимом с 1С (CSV с согласованным маппингом полей) |
| 8 | Интеграционный сервис | Отправляет email главному бухгалтеру: «Сверка за 01.06.2026 готова. Расхождений: 3. Ссылка на отчёт» |
| 9 | Финансовый отдел | Проверяет отчёт, разбирает расхождения (если есть), загружает в 1С |

## Формат отчёта сверки

| Поле | Источник | Описание |
|------|----------|----------|
| `date` | Период сверки | Дата, за которую выполняется сверка |
| `order_id` | OMS | ID заказа в маркетплейсе |
| `delivery_order_id` | FastDelivery | ID заказа в системе доставки |
| `amount_oms` | OMS | Сумма заказа в OMS |
| `amount_fd` | FastDelivery | Сумма в акте FastDelivery |
| `status_oms` | OMS | Статус в OMS |
| `status_fd` | FastDelivery | Статус в FastDelivery |
| `match_status` | Система | `MATCH` / `AMOUNT_MISMATCH` / `OMS_ONLY` / `FD_ONLY` / `STATUS_MISMATCH` |

## Alternative Flows

### 2a. OMS недоступна
1. Интеграционный сервис не может получить данные из OMS
2. Ретрай 3 раза с интервалом 5 минут
3. Если OMS не восстановилась → алерт дежурной смене
4. Сверка откладывается. Выполняется при следующем запуске cron. Бухгалтер получит отчёт за 2 дня

### 3a. FastDelivery API сверки недоступен
1. Интеграционный сервис не получает ответ от FastDelivery
2. Ретрай 3 раза с интервалом 5 минут
3. Если FastDelivery не восстановился → алерт дежурной смене + email бухгалтеру: «Сверка за [дата] отложена»
4. При восстановлении сверка запускается вручную бухгалтером

### 6a. Обнаружены расхождения
1. Система формирует отчёт с пометками `AMOUNT_MISMATCH`, `OMS_ONLY`, `FD_ONLY`
2. Бухгалтер получает email: «Сверка за [дата] готова. Расхождений: N»
3. **AMOUNT_MISMATCH:** Бухгалтер связывается с менеджером логистики. Возможные причины: доплата за негабарит, скидка, ошибка
4. **OMS_ONLY:** Заказ есть в OMS, но не у FastDelivery. Возможные причины: сбой при создании заказа, заказ передан вручную без обновления OMS
5. **FD_ONLY:** Заказ есть у FastDelivery, но не в OMS. Возможные причины: тестовый заказ, заказ другого клиента FastDelivery (ошибка фильтрации по API-ключу)
6. Бухгалтер инициирует разбор каждого расхождения
7. После разбора бухгалтер вручную корректирует статус расхождения в отчёте

## Postconditions
- Отчёт сверки сформирован и сохранён
- Бухгалтер уведомлен по email
- При отсутствии расхождений — данные готовы к загрузке в 1С
- При наличии расхождений — инициирован разбор
